# 服务端「有线投屏画面位置」修复 · 接入说明

## 1. 问题根因（实证）

参考 `fkun1754/HwVRGlassLite` 的 `desktop-mode/src/main.cpp:778`：

> 华为 VR Glass（CV10）物理面板是**两块 1600×1600 正方形屏**，左眼那块顺时针 90°、右眼逆时针 90° 安装（排线方向所致）。

本仓库服务端投屏链路：

- `DesktopCapture::AcquireFrame()` 把桌面居中 blit 到两块方形画布（`m_canvasTextures[0/1]`）；
- `CEncoder::RenderCastFrame()` 用 `bounds={0,0,1,1}` + **单位 pose** 把这两块画布直送 `RenderFrame` → 编码。

两处都**没有补偿面板的物理 ±90° 旋转**，所以用户在眼镜里看到的投屏画面是**两眼各躺倒 90°且方向相反**——这就是「画面位置问题」。

## 2. 修复原理

单眼画布是正方形（1600×1600），±90° 旋转不改变尺寸。因此在 **blit 到画布时**对每眼做一次反向 roll 即可，代价为零、不影响 pose/编码链路：

- 左眼画布：反向旋转 **+90°**
- 右眼画布：反向旋转 **-90°**
- HwVRGlassLite 提供 4 种组合（PP/MP/PM/MM）循环校准不同批次面板，本模块默认 PM（`+90,-90`，CV10 常见）。

算法核心已实现为纯 C 模块 `frame_roll_fix/`（`gcc` 单测 18/18 通过，并已交叉编译出 Windows 静态库 `libframe_roll_fix.a`）。

## 3. 接入方式（两选一）

### 方式 A：图层 pose 补偿（改动小，推荐先试）

在 `CEncoder::RenderCastFrame()` 里，把 1 个图层携带的单位 pose 换成**每眼 roll 的四元数→矩阵**。由于 `RenderFrame` 的 pose 是「每图层一个、左右眼共用」，需要把投屏拆成**两个图层**：

```cpp
// CEncoder.cpp  RenderCastFrame() —— 修改后片段
#include "frame_roll_fix.h"   // 新增

    FrConfig rollCfg;
    fr_config_default(&rollCfg);           // 默认 CV10 (+90,-90)

    // 每只眼一个图层，各带自己的 roll pose
    ID3D11Texture2D* layers[2][2] = {
        { eyeTextures[0], eyeTextures[0] },   // 图层0：仅左眼可见纹理
        { eyeTextures[1], eyeTextures[1] },   // 图层1：仅右眼可见纹理
    };
```

> 注意：`RenderFrame` 每个图层会**同时**渲染左右眼，拆两图层无法做到「图层0只有左眼、图层1只有右眼」。因此**方式 A 不可行**，改用方式 B。

### 方式 B：画布纹理空间 roll blit（正确方案）

在 `DesktopCapture::AcquireFrame()` 的 blit 阶段，把 `CopySubresourceRegion`（不支持旋转）换成一个带旋转 UV 的 quad blit。关键改动：

```cpp
// DesktopCapture.cpp  AcquireFrame() —— 修改后片段
#include "frame_roll_fix.h"   // 新增

    FrConfig rollCfg;
    fr_config_default(&rollCfg);

    for (int i = 0; i < 2; i++) {
        context->ClearRenderTargetView(m_canvasRtv[i].Get(), black);
        const int32_t posX = offsetX + (i == 0 ? -separation : separation);
        if (posX < 0 || (uint32_t)(posX + m_desktopWidth) > m_canvasWidth) continue;

        // 原：context->CopySubresourceRegion(...)
        // 新：带 ±90° roll 的 UV quad blit
        float roll = fr_eye_roll(&rollCfg, i);   // 左 +90 / 右 -90
        // 用 roll 构造旋转后的 4 个顶点 UV（fr_rotate_uv 逐顶点计算），
        // 以 m_canvasRtv[i] 为 RT、m_desktopTexture 为 SRV，画一个全屏 quad。
        DrawRolledQuad(context, m_desktopTexture.Get(), m_canvasRtv[i].Get(),
                       posX, offsetY, m_desktopWidth, m_desktopHeight, roll);
    }
```

`DrawRolledQuad` 用 `FrameRender` 已有的顶点/像素着色器基础设施即可（同样的全屏三角带 + 采样 SRV），只是顶点 UV 由 `fr_rotate_uv(u,v,roll,&ou,&ov)` 生成。

单眼画布为正方形，`fr_rotate_uv` 对 ±90° 的映射（已单测验证）为：

- `+90°`：`(u,v) → (1-v, u)`（源左上角转到右上角）
- `-90°`：`(u,v) → (v, 1-u)`

## 4. 校准不同面板批次

若某批眼镜画面方向仍不对，循环 stage 即可（`fr_next_stage`）：

```cpp
rollCfg.stage = fr_next_stage(rollCfg.stage);  // PP→MP→PM→MM→PP
```

4 种组合覆盖所有面板安装方向。也可用 `rollCfg.roll_override[eye]` 做非 90° 精细微调。

## 5. 旁路（普通串流，非华为面板）

```cpp
rollCfg.enabled = 0;   // fr_eye_roll 返回 0，画面不旋转
```

## 6. 验证状态

- `frame_roll_fix` 算法：`gcc` 单测 **18/18 PASS**（含 UV 旋转、stage 循环、SBS 分眼、swap）。
- Windows 静态库 `libframe_roll_fix.a`：mingw 交叉编译成功（`current ar archive`）。
- `CEncoder.cpp`/`DesktopCapture.cpp` 的实际 D3D11 blit 改动：需在有 **OpenVR headers/lib**（本仓库 `openvr` 子模块为空）的 Windows 环境编译验证，见 `docs/`。
