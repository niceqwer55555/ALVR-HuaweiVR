# 高通解码器策略（禁软解）

## 一、为什么锁定高通 + 禁软解

参考仓库在骁龙设备（一加 7T / sm8150）上的纯色画面根因已定位：
1. 平台被写死为 `HuaweiVrGlass` → `use_hisi_decoder = platform.is_huawei() && H264 && !force_sw`
2. 硬编码找 `OMX.hisi.video.decoder.avc`（华为麒麟专用），骁龙上不存在
3. 退回软解 `c2.android.avc.decoder`，拿不到硬件帧（ImageReader 输出纯色）
4. 眼镜合成链路本身正常，问题在视频内容层

本工程从源头消除：解码器选择与平台解耦，显式锁定高通组件，**禁止软解**。

## 二、候选链

| 编码 | 首选（Codec2） | 兼容（OMX） | 软解（默认禁用） |
|---|---|---|---|
| H.264 | `c2.qti.avc.decoder` | `OMX.qcom.video.decoder.avc` | `c2.android.avc.decoder` |
| H.265 | `c2.qti.hevc.decoder` | `OMX.qcom.video.decoder.hevc` | `c2.android.hevc.decoder` |

选择逻辑（`src/decoder/decoder_policy.c` 的 `ga_decoder_pick`）：
```
1. 用户覆盖名（若配置）→ 命中候选链且非软解才接受
2. 高通硬解候选链逐个探测可用性，返回第一个
3. 软解兜底：仅 allow_software=true 才进入（默认 false）
4. 全部不可用 → 返回 NULL → 调用方报错，绝不静默软解
```

## 三、MediaCodec 探测（Java 侧）

```java
MediaCodecList list = new MediaCodecList(MediaCodecList.ALL_CODECS);
for (String want : qcomCandidates) {
    for (MediaCodecInfo info : list.getCodecInfos()) {
        if (!info.isEncoder() && want.equalsIgnoreCase(info.getName()))
            return want;  // 找到高通硬解
    }
}
// 没找到 → 报错，不 fallback 到软解
```

`AlvrActivity.pickQualcommDecoder()` 已实现该逻辑。

## 四、与 C/Rust 配置一致性

三处保持同一候选链，改一处需同步：
- `src/decoder/decoder_policy.c`（C 运行时）
- `rustsrc/src/client_config.rs`（Rust 配置）
- `app/client_config.json`（下发配置）

单测已验证：候选链无任何 `hisi`、软解识别正确、禁软解时不静默降级。

## 五、缓冲参数

参考仓库 hisi 分支的硬件输出池较小，本工程沿用保守值：
- `max_buffering_frames = 3`
- `render_output_immediately = true`
- `retain_last_frame = true`

这些值在 `ga_decoder_default()` 里，可按真机表现调整。
