## 一（补）、本环境已产出的 APK

本交付环境已安装 JDK 17 + NDK r25c + build-tools 34 + platform-34，并产出可安装 APK：

```bash
cd 客户端3-安卓接收端(高通/去华为框架)
bash scripts/build_apk.sh
# 产物：build/GenericALVR-arm64.apk（v2/v3 签名，arm64-v8a）
```

> 注意：APK 是平台桥/诊断壳，可验证安装、JNI、传感器、解码器枚举和设备状态；不包含 ALVR 控制协议与视频解码，不能直接出串流画面。

验证结果：
- `libgeneric_alvr_bridge.so`：ELF aarch64，导出 15 个 JNI 符号，与 `AlvrActivity` 的 15 个 `native` 声明一一对应（含 `nativeGetControllerStatus` / `nativeSetControllerBattery` 三设备指示灯接口）。
- APK：`aapt2 dump badging` 显示 `native-code: 'arm64-v8a'`、`sdkVersion:24`、`targetSdkVersion:34`。
- 签名：`apksigner verify` 通过 v2 + v3 scheme。
- 打包脚本已修复两处缺陷：`AlvrActivity.java` 块注释内 `*/` 提前闭合、javac 需显式 `-encoding UTF-8`。

## 二、真机构建（在装有 Android SDK/NDK 的环境）

```bash
export ANDROID_NDK_HOME=/home/user/ndk/android-ndk-r25c
export ANDROID_SDK_ROOT=/home/user/platform
export OPENXR_HEADERS=/path/to/OpenXR-SDK/include   # 可选，编译标准 runtime 用

./scripts/build_apk.sh
```

脚本产出：
- `build/apk/lib/arm64-v8a/libgeneric_alvr_bridge.so` —— JNI 桥 + C 核心
- `build/apk/lib/arm64-v8a/libgeneric_alvr_xr.so` —— 通用 OpenXR runtime
- `build/apk/assets/active_runtime.json` —— 标准 loader 发现配置
- `build/apk/assets/client_config.json` —— 客户端配置

## 三、打包成 APK（完整步骤）

```bash
# 1. 资源编译
aapt2 compile --dir android/res -o build/compiled_flats/
aapt2 link -o build/base.apk \
  -I "$ANDROID_SDK_ROOT/platforms/android-34/android.jar" \
  --manifest android/AndroidManifest.xml \
  -R build/compiled_flats/*.flat \
  --java build/gen

# 2. 加入 native 库与 assets
cd build/apk && zip -r ../base_full.apk . && cd ..

# 3. javac 编译 Java host（含 R.java）
javac -cp "$ANDROID_SDK_ROOT/platforms/android-34/android.jar" \
  -d build/classes android/java/com/generic/alvr/*.java build/gen/**/R.java

# 4. dex + 合并
d8 --output build/apk/classes.dex build/classes/**/*.class
cd build/apk && zip -r ../final_unsigned.apk classes.dex && cd ..

# 5. 对齐 + 签名
zipalign -p -f 4 build/final_unsigned.apk build/aligned.apk
apksigner sign --ks my.keystore --out build/generic-alvr.apk build/aligned.apk
apksigner verify -v build/generic-alvr.apk
```

## 四、安装与运行

```bash
adb install -r build/generic-alvr.apk
adb logcat -s GenericAlvr          # 看状态（解码器/姿态源）
```

手机 USB-C 插眼镜后，App 以 `1600×1600` 单眼视图 / `3200×1600` 面板尺寸初始化 SurfaceView 与姿态桥；当前版本不会自动连接 ALVR server，也不会输出 SBS 串流画面。

## 五、配置说明

`app/client_config.json`：

| 字段 | 默认 | 说明 |
|---|---|---|
| `pose_source` | `phone-imu` | `phone-imu`=手机 IMU 自算；`udp-inject`=外部姿态 |
| `pose_udp_port` | 47110 | 外部姿态注入端口（localhost） |
| `codec` | `h264` | 与 ALVR server 编码一致 |
| `no_software_decoder` | `true` | **禁止软解**；无高通硬解则报错 |
| `left/right_controller_dof` | `6dof` | 每只手柄可设 `3dof`/`6dof` |
| `use_standard_loader` | `true` | 必须为 true（去华为 loader） |
| `decoder_override` | `null` | 可指定解码器名；含 `hisi` 会被自检拒绝 |

## 六、已知限制

- 本 APK 只覆盖平台桥/诊断壳：没有 ALVR 控制协议、视频解码、双目 SBS 渲染，不能直接串流。
- 完整串流客户端需要 `alvr_client_core` + OpenXR runtime；依赖的 `openxrs-huawei` 源码不在本仓库，需从授权来源补齐。
- 真机头显点亮 / 与 ALVR server 实机互通未在沙箱验证。
- 手柄输入目前为 native 聚合接口；蓝牙手柄 HID 配对与触摸虚拟手柄映射需真机适配。
- 通用手机无原生 6DoF：位置需外部 SLAM（ARCore/PC）经 UDP 注入。
