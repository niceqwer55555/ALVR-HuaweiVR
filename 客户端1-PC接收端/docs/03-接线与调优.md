# 接线、协议互通与延迟调优

## 1. 两端协同的必要条件

| 项 | 高配 PC（ALVR server） | 低配 PC（本接收端） |
|---|---|---|
| ALVR 版本 | v20.14.1 华为专版 | 协议按 v20.14.1 实现 |
| 版本校验 | 华为版已放宽（版本串不同也能连） | 如实上报 protocol_id=20 |
| 编解码 | H.264（验收档） | FFmpeg 解码 H.264 |
| 分辨率 | 编解码单眼 1536×1536（1.0×） | `view_resolution=[1536,1536]` |
| 刷新率 | 首选 72Hz，实际协商 70Hz | `target_fps=70`、能力集含 70/72 |
| 立体 | server 输出两眼合成帧 | `stereo_layout=sbs` 与之匹配 |
| 网络 | 有线/5GHz，同局域网 | 同上 |

**最容易踩的坑**：server 端"编解码单眼分辨率"与接收端 `view_resolution` 不一致 → 花屏/黑屏。两者必须一致。

## 2. 帧尺寸推导（SBS）

- server 编码单眼 `1536×1536`；
- 两眼合成一张 SBS 帧 → `3072×1536`；
- `decoder.rs` 的 `frame_size()`：`SBS → (w*2, h)`，`TB → (w, h*2)`；
- FFmpeg `-vf scale=3072:1536`，输出 BGRA 每帧 `3072*1536*4 ≈ 18 MB`；
- 经 TCP 9911 发给渲染器，渲染器 `sbsMode=1` 分眼 UV：左眼 u∈[0,0.5]、右眼 u∈[0.5,1]。

> 18 MB/帧 × 70fps ≈ 1.26 GB/s 的本地回环带宽。本机 TCP loopback 完全可承受，
> 但请注意这是**未压缩**帧；若想降带宽，可让 FFmpeg 直接输出 NV12 再在渲染器侧转，
> 属后续优化（本版用 BGRA 求稳）。

## 3. 延迟构成与优化

```
server 编码 ─► 网络 ─► FFmpeg 解码 ─► TCP 回环 ─► D3D11 上传 ─► Present ─► 眼镜
   5-15ms      2-10ms    10-30ms        <2ms        2-5ms       1帧        
```
优化点（按收益排序）：
1. **FFmpeg 去 B 帧重排**：在 `decoder.rs` 的 ffmpeg 参数加 `-tune zerolatency -bf 0`，可省约 1-2 帧延迟。
2. **硬解**：若低配 PC 的 GPU 有 NVENC Decode / VCN（作者实测 Valve OEM 驱动无媒体引擎），把 FFmpeg `-c:v h264_nvenc` 换成 `h264_cuvid` 等硬解。
3. **跟踪时钟同步**：`Tracking.target_timestamp` 当前填 0。ALVR 用 server 预测 + 客户端 `report_frame_decoded` 对齐；低延迟场景应接 NTP/PTP，让客户端时间戳与 server 同源。
4. **渲染器 `retain_last_frame`**：无新帧时保留上一帧，避免间歇黑屏（上游已有此语义）。

## 4. 头姿坐标系

- 上游 `DeviceMotion.pose.orientation` =四元数 `xyzw`（`alvr_common::Pose`）。
- IMU 给出的 `dm_imu.q[4]` = `w,x,y,z`（设备坐标系）。
- 补丁 C 发送时重排为 `x,y,z,w`（见 `docs/04`），与 Rust `PoseInput` 及 server 约定一致。
- 位置固定原点 `[0,0,0]`：3DoF。若要 2.5D 沉浸感，可用 IMU 加速度二次积分做短时位置外推，但会漂移，需与 server 的 `PlayspaceSync` 配合。

## 5. 手柄（未实现，接入指引）

若要补手柄，需在上游 `deps/huawei-driver/bin/win64/` 的华为驱动或 HID 上读 6DoF 手柄数据，映射为 ALVR 控制包：
- `ClientControlPacket::Buttons(Vec<ButtonEntry{path_id, value}>)` — 按键
- `ClientControlPacket::ActiveInteractionProfile{device_id, profile_id}` — 交互配置
- 华为 profile：`/interaction_profiles/huawei/6dof_controller`（3DoF 为 `/huawei/controller`）
- 注意作者踩坑：**绝不能同时建议两个 profile**（libvrsdk.so 崩溃）；3DoF/6DoF 分包。
- `path_id` 需与 server 端 `interaction.rs` 的 action 路径哈希一致，建议从上游 `huawei_input.rs` 提取。
