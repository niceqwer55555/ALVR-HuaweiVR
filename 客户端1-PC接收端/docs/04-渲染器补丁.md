# 渲染器补丁：让 HwVRDesktop 从网络收帧并回传 IMU

> 2026-11-25 已落地：源码在 `renderer-src/src/dm_netframe.{h,cpp}`，`main.cpp` 已切换视频源；
> `renderer/HwVRDesktop.exe` 是编译产物。下面的说明保留为改动依据。

> 目的：复用上游**已真机验证**的 SBS 渲染器（`deps/huawei-desktop/`），只改"视频源"。
> 不改 D3D11 渲染、曲面、畸变、SBS 分眼逻辑（那些已验证可用）。
> 补丁只做两件事：① 从 TCP 9911 收 BGRA 帧替代 DXGI 桌面采集；② 从 HID 读 IMU 四元数经 UDP 9912 发给 Rust。

## 0. 为什么这么做

上游 `HwVRDesktop.exe` 真机日志（2026-11-23）已确认：
- 找到眼镜屏 DISPLAY2 3200×1600、采集 DISPLAY1、每眼 2400×2400 超采样、`Present hr=0` 持续送画、`frame_dump.bmp` 目视是左右双目+曲面+桌面内容。
- 关键点 `RenderFrame()` 里：`g_gfx.DrawQuad(..., g_cap.srv, ...)` —— **`g_cap.srv`（桌面采集纹理）就是唯一视频源**。

所以只要把 `g_cap.srv` 换成"网络帧纹理"，其余渲染管线原样可用。

## 1. 改动清单（共 3 处，约 120 行）

### 改动 A：新增网络帧源模块 `dm_netframe.h / dm_netframe.cpp`

职责：作为 TCP **server** 监听 `127.0.0.1:9911`，收 `hvr-alvr-win-sink` 发来的帧：
```
[u32 宽 LE][u32 高 LE][u32 布局 LE][BGRA 像素 w*h*4]
```
把 BGRA 上传到 `ID3D11Texture2D`，提供 `srv`（ShaderResourceView）给渲染用。

```cpp
// dm_netframe.h
#pragma once
#include <windows.h>
#include <d3d11.h>
#include <thread>
#include <vector>
#include <atomic>

struct DmNetFrame {
    ID3D11Device* dev = NULL;
    ID3D11DeviceContext* ctx = NULL;
    ID3D11Texture2D* tex = NULL;
    ID3D11ShaderResourceView* srv = NULL;
    uint32_t w = 0, h = 0;
    std::atomic<bool> ready{false};
    std::atomic<bool> run{false};
    volatile LONG frames = 0;

    void Start(ID3D11Device* d, ID3D11DeviceContext* c);
    void Stop();
    bool Acquire();          // 收到新帧时上传纹理，返回 true
    // 关键：让外部把 srv 当作视频源
    ID3D11ShaderResourceView* Srv() const { return srv; }
};
```

`dm_netframe.cpp` 要点：
- `Start()`：起线程 `socket(AF_INET, SOCK_STREAM)` → `bind(127.0.0.1:9911)` → `listen(1)` → `accept()`；
- 循环读 12 字节头 → 按 `w*h*4` 读像素；
- 用 `dev->CreateTexture2D`（`B8G8R8A8_UNORM`, `D3D11_BIND_SHADER_RESOURCE`）+ `ctx->UpdateSubresource` 上传；
- 若尺寸变化则重建纹理；
- `ready=true` 表示有新帧；`srv` 供渲染读取。
- 注意：`UpdateSubresource` 的 row pitch 必须是 `w*4`（BGRA 连续）。

### 改动 B：main.cpp 里替换视频源（核心一行）

在 `RenderFrame()` 中（约 834 行）：
```cpp
// 原：
if (!g_screenHidden && g_st.opacity > 0.001f && g_cap.srv) {
    ...
    g_gfx.DrawQuad(screenMesh.data(), ..., g_cap.srv, ...);
}
// 改：
ID3D11ShaderResourceView* videoSrv = g_netframe.Srv();   // 新增
if (!g_screenHidden && g_st.opacity > 0.001f && videoSrv) {
    ...
    g_gfx.DrawQuad(screenMesh.data(), ..., videoSrv, ...);  // ← 换成 videoSrv
}
```
同时把 `sbsMode` 固定为 1（SBS Half，左右各半）——这与 ALVR 合成的 SBS 帧一致：
- 上游 `sbsMode=1` 的分眼 UV 逻辑（`main.cpp` 838-845 行）已经是：`rightEye` 取 `u0=0.5,u1=1.0`，左眼 `u0=0,u1=0.5`，**正好匹配**。

其余：
- 初始化处（约 1010 行 `g_cap.Start(...)` 之后）加 `g_netframe.Start(g_gfx.dev, g_gfx.ctx);`
- 主循环（约 1298 行 `g_cap.Acquire()` 处）改为 `g_netframe.Acquire();`
- 退出（约 1419 行 `g_cap.Stop()`）加 `g_netframe.Stop();`

### 改动 C：IMU 四元数经 UDP 回传 Rust

上游 `dm_imu.cpp` 已经用 Mahony 得到 `g_imu.q[4]`（w,x,y,z）。在主循环里（约 1286 行 `g_imu.GetQuat(...)` 之后）加一个 UDP 发送：
```cpp
// 新增：把四元数发给 hvr-alvr-win-sink（注意 Rust 侧约定 xyzw）
float w, x, y, z;
g_imu.GetQuat(&w, &x, &y, &z);
float pkt[4] = { x, y, z, w };   // ← Rust 侧是 xyzw
sendto(imuSock, pkt, sizeof(pkt), 0, (sockaddr*)&sinkAddr, sizeof(sinkAddr));
// sinkAddr = 127.0.0.1:9912，程序启动时建一个 UDP socket
```
这样 Rust 的 `PoseInput` 就能收到头姿，回传给 ALVR server。

## 2. 帧时序与延迟

```
server 编码 70fps → NAL → [网络] → Rust 解码 → BGRA → [TCP 9911] → 渲染器 → D3D11 → 眼镜
                                                                          ↑ IMU → [UDP 9912] → Rust → tracking → server
```
- 渲染器每帧调 `g_netframe.Acquire()`，若 `ready` 则 `UpdateSubresource`；
- 无新帧时保留上一帧纹理（上游已有 `retain_last_frame` 语义），避免黑屏；
- 延迟主要来自 FFmpeg 解码缓冲，可在 `decoder.rs` 的 ffmpeg 参数里去掉 B 帧重排（`-tune zerolatency`）。

## 3. 编译

用上游现成脚本（已处理 MinGW / DPI / `WM_PAINT` / 格式一致等所有坑）：
```powershell
pwsh -NoProfile -File .\scripts\huawei\build-desktop-mode.ps1
```
它会把 `deps/huawei-desktop/src/*.cpp` 编成 `HwVRDesktop.exe`（静态链接，无依赖 DLL）。
把新增的 `dm_netframe.cpp` 放进同目录即可被通配符 `*.cpp` 自动纳入编译。

## 4. 验证顺序（在你自己的 Windows + 真机上）

1. 先不接 Rust，确认原版 `HwVRDesktop.exe` 能点亮眼镜（上游已验证，作为基线）。
2. 应用补丁 A/B，启动渲染器；用任意 TCP 客户端发一帧测试 BGRA（脚本 `scripts/send_test_frame.py`），确认眼镜显示该帧。
3. 应用补丁 C，确认 Rust 能收到 IMU（日志打印四元数）。
4. 全链路：高配 PC 开 ALVR Dashboard → 低配 PC 先后启动 `HwVRDesktop.exe` 再启动 `hvr-alvr-win-sink.exe` → 观察画面与头动。
