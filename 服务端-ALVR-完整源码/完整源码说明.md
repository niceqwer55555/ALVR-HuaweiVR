# ALVR-HuaweiVR 服务端完整源码说明

本目录由 `服务端-ALVR`（原仓库精选摘录）与完整上游工程
`HuaweiVRGlass-ALVR` 合并而成，目标是得到一棵**可被 Cargo 解析、可构建服务端/Dashboard**
的完整源码树，而不是继续保留只有部分文件的摘录。

## 合并方式

| 原摘录路径 | 合并后路径 |
|---|---|
| `server-core/src` | `alvr/server_core` |
| `server-core/server_io` | `alvr/server_io` |
| `公共crate/*` | `alvr/*` |
| `server-openvr` | `alvr/server_openvr` |
| `官方编译脚本/huawei` | `scripts/huawei` |

其余文件（`alvr/dashboard`、`alvr/launcher`、`alvr/xtask`、`alvr/client_*`、`openvr/headers`、
`deps/huawei-desktop`、根 `Cargo.toml`/`Cargo.lock`）取自完整上游工程，补上了摘录包缺失的
工程骨架。`HUAWEI_VR_GLASS.md` 与 `本地依赖patch/` 保留在根目录。

## 关键补齐

- **根 `Cargo.toml`**：工作区成员显式列出服务端、Dashboard、launcher、xtask 等 19 个 crate；
  `alvr/client_core`、`client_mock`、`client_openxr` 不在成员内。原因是它们依赖上游的
  `deps/openxrs-huawei` 私有 fork，本包不含该 fork；服务端构建不需要它们。
- **`deps/wgpu-hal-huawei`**：放入 `wgpu-hal 24.0.0` 官方源码，并只增加一个空 feature
  `huawei-vr-egl = []`。`alvr/graphics` 用到的 `Adapter::new_external` 官方 24.0.0 已有，
  因此这是可编译的本地补丁，不是空壳 crate。
- **`openvr`**：保留 `headers`、`lib`（含 Windows/ Linux 的 `openvr_api`）、许可证；
  删除 400+ MB 的 samples/bin，避免源码包无意义膨胀。
- **`scripts/huawei`**：脚本里的相对路径与合并后的 `alvr/*`、`deps/*` 布局一致。

## 未包含（非源码或私有依赖）

- `deps/huawei-driver`、`deps/huawei-usb-driver`：厂商签名驱动二进制，不属于源码；打包安装器时
  需从原发布包拷回。
- `deps/openxrs-huawei`：华为 OpenXR 私有 fork，仓库未公开；只影响 Android 客户端 crate。
- `deps/ffmpeg`：`alvr_server_openvr/build.rs` 会断言 `ffmpeg/include` 存在。构建串流端前需按
  `scripts/huawei/README.md` 放置 FFmpeg 开发包（Windows 推荐 gpl-shared）。

## 已验证

在 Linux + `x86_64-pc-windows-gnu` 交叉目标上执行：

```bash
cargo metadata --no-deps          # 19 个 workspace 包，全部解析成功
cargo check -p alvr_server_io  --target x86_64-pc-windows-gnu   # 通过
cargo check -p alvr_graphics   --target x86_64-pc-windows-gnu   # 通过（wgpu-hal 本地 patch）
cargo check -p alvr_server_core --target x86_64-pc-windows-gnu  # 通过
cargo check -p alvr_dashboard  --target x86_64-pc-windows-gnu   # 通过（1 个 unused import 警告）
```

`alvr_server_openvr` 的 `cargo check` 在 `build.rs` 因缺少 FFmpeg 开发目录停止，属于依赖缺失，
不是源码缺失。Linux 原生构建 `alvr_server_core` 还会被系统 `libpipewire 0.3.48` 与
`pipewire 0.8` 的 `v0_3_49` feature 不匹配卡住；Windows 目标不受影响。

## 构建入口

```powershell
# Windows x64，需 MSVC + Windows SDK + FFmpeg 开发包
cargo build --release -p alvr_server_core
cargo build --release -p alvr_dashboard
# 或使用华为脚本
powershell scripts/huawei/build-streamer-gpl.ps1
powershell scripts/huawei/build-desktop-mode.ps1
```

服务端与 PC 接收端的协议常量、分片长度语义以 `alvr/sockets`、`alvr/packets` 为准；
PC 端修复已对齐本目录的服务端实现。
